모델을 구성하고 실행하는 기초

y = max(0, x × 2 − 1)이라는 작은 계산을 기준으로 구분한다. 이 계산을 설명한 시작 페이지와 같은 의미다.

용어 작은 예 뜻과 주의할 점
모델, model 곱하기 → 빼기 → 음수를 0으로 바꾸기 입력에서 출력을 만드는 계산 구조와 그 계산에 사용하는 매개변수를 함께 말한다. 모델 이름만으로 실제 장치 코드가 준비되지는 않는다.
가중치·매개변수, weight·parameter 곱할 값 2, 보정값 −1 모델이 보관하는 값이다. 학습으로 정할 수 있고, 일반적인 추론에서는 고정해 여러 요청에 재사용한다. 입력 x와 구별한다.
추론, inference x=3을 넣어 y=5를 구하기 준비된 모델의 규칙과 매개변수로 새 입력의 출력을 계산한다. 이 책의 장치 실행 설명은 주로 추론을 다룬다.
학습, training 예측과 정답의 차이를 줄이도록 2와 −1을 수정 모델의 매개변수를 조정하는 과정이다. 한 번 추론을 실행하는 것과 목적·필요한 계산이 다르다.
커널, kernel 곱하기만, 또는 곱하기·보정·ReLU를 묶은 장치 함수 장치가 수행할 계산 단위다. 여러 연산을 묶거나 한 연산을 여러 커널로 나눌 수 있어, 수학식의 기호 수와 커널 수가 같지는 않다.
ReLU max(0, −1)=0, max(0, 5)=5 Rectified Linear Unit. 음수는 0으로, 0 이상은 그대로 두는 함수다. 배열에서는 각 원소에 적용한다.
체크포인트, checkpoint 저장한 가중치와 학습 상태 등 다시 읽어 모델을 구성하거나 학습을 이어갈 때 쓰는 저장물이다. 포함 항목은 형식에 따라 다르며, 가중치 파일을 곧바로 NPU 실행 바이너리로 보지 않는다.

TCP Tensor Contraction Processor 텐서 축을 결합·축약하는 contraction을 중심으로 설계한 프로세서 아키텍처. 네트워크의 TCP와 문맥이 다르다. 1장 하드웨어
PE Processing Element RNGD 안의 계산 자원 단위. 한 장치의 PE 수와 여러 장치의 카드 수를 구분한다. 1장 하드웨어, 15장 여러 NPU
Cluster Cluster PE들을 묶는 칩 내부의 공간 계층. vISA에서 어떤 축을 어느 자원에 펼칠지 설명할 때 등장한다. 1장 하드웨어, 8장 vISA
Slice Slice PE 내부의 더 작은 공간 단위. 텐서 배치가 slice에 분산되는 방식은 메모리 접근과 계산 병렬성에 영향을 준다. 1장 하드웨어
Lane Lane slice 내부의 세부 데이터·연산 배치 단위. Python 텐서의 축 이름과 자동으로 일치하는 것은 아니다. 1장 하드웨어, 8장 vISA
HBM High Bandwidth Memory 장치가 사용하는 큰 고대역폭 메모리. 가중치·입력·중간값·KV cache가 용량과 대역폭을 함께 사용한다. 2장 메모리와 DMA
SRAM Static Random Access Memory RNGD 칩 안의 빠른 메모리를 설명할 때 쓰는 메모리 기술명. HBM보다 용량이 작아 재사용·배치가 중요하다. 1장 하드웨어, 2장 메모리와 DMA
DM Data Memory vISA에서 명시적으로 다루는 온칩 데이터 메모리 공간. bank와 주소 배치가 전송 효율에 영향을 준다. 2장 메모리와 DMA
SPM Scratchpad Memory 중간 데이터 등을 명시적으로 배치하는 scratchpad 공간. 범용 CPU의 자동 캐시처럼 가정하지 않는다. 2장 메모리와 DMA
TRF Tensor Register File 텐서 계산 가까이에 값을 잠시 보관하고 재사용하는 하드웨어 레지스터 저장소. 여기서 file은 디스크 파일이 아니라 레지스터의 묶음이다. 용량·배치 제약이 타일과 스케줄 선택에 연결된다. 1장 연산 파이프라인, 8장 vISA
VRF Vector Register File 벡터 연산에서 값을 보관하는 하드웨어 레지스터 저장소. TRF와 별도의 역할·접근 경로를 가지며 저장 장치의 파일이 아니다. 1장 연산 파이프라인
DMA Direct Memory Access CPU가 모든 데이터를 직접 복사하는 대신 전용 엔진이 메모리 사이의 이동을 수행하는 방식. 완료와 의존성 관리는 여전히 필요하다. 2장 메모리와 DMA
PDMA PCIe DMA host와 장치 HBM 사이를 PCIe로 이동하는 DMA 경로. 전송을 시작했다는 사실과 완료했다는 사실이 다르다. 2장 메모리와 DMA
TDMA Tensor DMA 장치 내부 텐서 이동에 사용하는 DMA 경로. 복사와 함께 배치·변환을 생각해야 한다. 2장 메모리와 DMA

EDF Executable Device Format 컴파일된 장치 실행물. SDK와 opt 문맥의 같은 명칭이 직렬화 포맷·ABI의 동일성이나 교차 적재 가능성을 보장하지 않는다. 4장 TCL과 EDF, 8장 vISA·Image
Device Function Image Device Function Image opt runtime이 적재하는 장치 함수 이미지. 코드와 인수·topology 등 런타임 계약을 함께 확인해야 한다. 8장 vISA·Image
Relocation Relocation 미리 정하지 못한 주소 참조를 실제 배치에 맞게 연결·수정하는 처리. 공개 opt에서 확인한 것은 host 실행 파일의 registry 참조 relocation이며, 매 launch의 buffer 바인딩 및 SDK EDF 내부 코드 재배치와 구분한다. 8장 relocation 범위
NoC Network-on-Chip 칩 내부 구성 요소들을 연결하는 통신망. 메모리 병목·전송 충돌의 영향이 timeout 등으로 드러날 수 있다. 2장 메모리와 DMA

PERT의 공식 확장은 PE Runtime이다. 공식 소프트웨어 스택은 PE를 Processing Element로 풀고 펌웨어·PERT·host runtime의 책임을 구분한다. EDF의 풀네임은 공식 Kernel Validation에서 확인했다. 이전 판의 “EDF 풀네임 미확인” 표기를 이 근거에 따라 수정했다.

커널·축·자료형

용어 풀네임 또는 공식 표기 쉽게 읽는 의미 관련 장
TCL Tensor Contraction Language 텐서 축과 contraction을 표현하는 Furiosa의 Python 기반 커널 언어. 일반 Python 실행 결과를 저장하는 방식과 다르다. 4장 TCL과 EDF
eDSL embedded Domain-Specific Language Python·Rust 같은 host 언어 안에 들어 있는 특정 분야용 언어. 여기서는 컴파일 가능한 tensor 계산 표현을 만든다. 4장 TCL과 EDF, 8장 vISA
vISA Virtual Instruction Set Architecture 장치의 계산·메모리·스케줄을 표현하는 컴파일러 중간 표현(IR). Rust eDSL과 furiosa-opt 도구로 다루며, 실행기는 vISA 텍스트 자체가 아니라 컴파일된 실행물을 적재한다. 8장 vISA와 eISA의 경계
eISA 공식 풀네임·독립 공개 API 미확인 요청에서 언급된 표기. 이 책은 공개 근거 없이 vISA의 동의어로 바꾸거나 별도 실행법을 만들지 않는다. 8장 vISA와 eISA의 경계
Axis Axis 텐서의 차원에 붙인 의미 있는 축. 행렬곱의 M,K,N에서 K를 축약하고 M,N을 출력에 남길 수 있다. 4장 TCL과 EDF, 7장 최적화
Shape Shape 각 차원의 길이. 컴파일된 커널이 허용하는 shape와 실제 입력 shape가 맞아야 한다. 6장 Shape와 버킷
Stride Stride 논리 인덱스를 하나 움직였을 때 실제 저장 위치가 얼마나 이동하는지 나타내는 값. 같은 shape도 stride에 따라 배치가 다르다. 2장 메모리와 DMA, 11장 컴파일 경로
Mapping Mapping 논리 텐서 축을 cluster·PE·slice·lane 및 시간 방향에 대응시키는 결정. 같은 수식도 다른 mapping으로 이동량이 달라질 수 있다. 7장 최적화, 8장 vISA
Fusion Fusion 문맥에 따라 여러 연산을 결합하는 최적화 또는 SDK에서 PE 구성을 정하는 값을 뜻한다. set_fusion(8)을 “연산 8개 합치기”로 읽지 않는다. 3장 소프트웨어 계층, 7장 최적화
Reduction Reduction 합·최댓값처럼 축의 여러 값을 모아 출력의 축을 줄이는 연산. contraction의 축약과 연결되지만 모든 reduction이 행렬곱은 아니다. 4장 TCL과 EDF, 9장 ATen
BF16 bfloat16 16비트 부동소수점 형식. 입출력이 BF16이어도 내부 누산 형식은 따로 확인한다. 1장 하드웨어, 4장 TCL과 EDF
FP8 8-bit Floating Point 8비트 부동소수점 형식의 계열. “FP8 지원”이라는 이름만으로 실제 format·scale·양자화 계약까지 같다고 볼 수 없다. 1장 하드웨어, 13장 모델 포팅

공식 TCL 소개와 furiosa-opt 소개를 기준으로 언어와 실행 도구를 구분했다. eISA의 미확인 상태는 8장에서 조사 범위와 함께 설명한다.

Torch의 연산 경계

용어 풀네임 또는 공식 표기 쉽게 읽는 의미 관련 장
ATen A Tensor Library PyTorch의 텐서 연산 계층. aten::mm 같은 연산은 장치의 기계 명령어 한 개를 뜻하지 않는다. 9장 Torch와 ATen
Operator schema Operator schema 연산 이름·인수·기본값·출력·변이 등의 호출 계약. 지원 범위를 셀 때 단순 이름과 구분한다. 9장 Torch와 ATen
Overload Overload 같은 기본 연산 이름의 서로 다른 호출 형태. Tensor, Scalar, out 등은 같은 테스트 하나로 대체되지 않는다. 9장 Torch와 ATen
Dispatcher Dispatcher 현재 연산과 인수·실행 문맥에 맞는 구현을 고르는 PyTorch 계층. 매 호출마다 컴파일한다는 뜻은 아니다. 9장 Torch와 ATen
Dispatch key Dispatch key 장치·autograd 등 구현 선택에 관여하는 구분자. torch.compile의 backend 등록과는 다른 등록 경계다. 9장 Torch와 ATen
FX torch.fx, 공식 API 이름 PyTorch 프로그램을 그래프로 표현·변환하는 도구. 이 책에서는 확인하지 않은 영문 풀네임을 붙이지 않는다. 9장 Torch와 ATen, 11장 컴파일 경로
Decomposition Decomposition 상위 연산을 다른 기본 연산들의 조합으로 바꾸는 규칙. 분해 규칙이 있다는 사실만으로 생성된 모든 연산의 NPU 지원이 보장되지는 않는다. 9장 Torch와 ATen, 11장 컴파일 경로

Torch 용어는 ATen 문서, Dispatcher 설명, FX 문서를 참고한다. 이 책의 연산 개수는 버전과 집계 단위를 고정한 결과이며 용어 자체의 영구 속성이 아니다.

프로젝트와 실행 산출물

용어 풀네임 또는 공식 표기 쉽게 읽는 의미 관련 장
FXB Furiosa Executable Bundle Furiosa가 공식 지원하는 실행 bundle 형식. manifest와 EDF를 포함하며 필요한 모델 assets의 계약은 별도로 확인한다. 3장 소프트웨어 계층, 12장 fxbX
fxbX fxbX, 프로젝트명 FuryNo5가 만든 실행 계획과 실행물 등을 포장·검사·적재하는 사용자 프로젝트. 공식 FXB 지원과 동의어가 아니다. 12장 fxbX
FuryNo5 FuryNo5, 프로젝트명 Torch 그래프의 의미를 분석하고 TCL·EDF·실행 계획을 생산하는 프로젝트. 실제 import 이름은 tclmachine이며 현재 전체 ATen 구현 완료를 뜻하지 않는다. 10장 FuryNo5 구조
FHA Furiosa-Hug-Anything 모델 포팅 절차·연결·검증을 자동화하는 프로젝트. FuryNo5의 연산 생산자 및 fxbX의 실행 소비자 역할과 구분한다. 13장 모델 포팅
FuryAwesome FuryAwesome, 프로젝트명 포팅 모델의 사용법·배포 링크·검증 정보를 공유하고 요청을 모으는 카탈로그. 컴파일러나 장치 런타임이 아니다. 13장 역할과 게시
Manifest Manifest 패키지의 구성 요소·속성·참조를 설명하는 메타데이터. 확장자보다 실제 schema와 계약을 검사한다. 12장 fxbX
Fingerprint Fingerprint 소스·컴파일 옵션·SDK·입출력 계약 등의 동일성을 판단하기 위해 기록하는 식별값. 파일 이름만 같은 캐시의 잘못된 재사용을 막는 데 쓴다. 11장 컴파일 경로
Execution plan Execution plan 이 책의 FuryNo5 문맥에서는 EDF 호출 순서와 tensor 연결·상태·수명을 표현한 계획. 서비스 요청 순서나 커널 내부 스케줄과 구분한다. 5장 그래프와 폴백, 12장 fxbX

공식 FXB 문서와 사용자 프로젝트의 FuryNo5 README권한 필요, fxbX README, FHA 역할 설명권한 필요을 서로 다른 근거로 읽는다.

LLM 실행과 서빙

용어 풀네임 또는 공식 표기 쉽게 읽는 의미 관련 장
LLM Large Language Model 큰 언어 모델. 가중치만 실행하는 문제에 더해 요청·토큰·상태·KV cache의 수명 관리가 필요하다. 3장 소프트웨어 계층, 14장 vLLM 서빙
KV cache Key–Value cache attention에서 이미 계산한 토큰의 key와 value를 보존한 상태. 어느 요청·layer·block의 데이터인지 추적해야 한다. 6장 Shape와 버킷, 14장 vLLM 서빙
Prefill Prefill 프롬프트 토큰을 처리하고 이후 생성에 필요한 상태를 준비하는 단계. 프롬프트 길이가 실행 shape에 큰 영향을 준다. 6장 Shape와 버킷
Decode Decode 이전 상태를 사용해 후속 토큰을 생성하는 반복 단계. 활성 요청 수·현재 context·cache 배치가 실행 비용에 영향을 준다. 6장 Shape와 버킷, 14장 vLLM 서빙
Bucket Bucket 허용하는 입력·배치·토큰 규격 등을 묶어 미리 준비한 실행 선택지. 하드웨어 부품이나 KV cache block과는 다른 개념이다. 6장 Shape와 버킷
TP Tensor Parallelism 하나의 계산을 여러 계산 자원에 나누는 병렬화. 공식 Furiosa-LLM의 PE 단위와 opt plugin의 chip 단위 설정을 구분한다. 15장 여러 NPU
PP Pipeline Parallelism 모델의 단계·층을 여러 자원에 나누고 데이터가 순서대로 지나가게 하는 병렬화. 단계 간 전송과 pipeline 대기 비용이 생긴다. 15장 여러 NPU
DP Data Parallelism 모델 복제본들이 서로 다른 요청·데이터를 처리하는 병렬화. 각 복제본의 가중치와 cache 용량이 필요하다. 15장 여러 NPU
TTFT Time To First Token 요청 후 첫 토큰을 받기까지의 시간. 큐 대기·prefill·초기 실행 등 측정에 포함한 범위를 함께 기록한다. 6장 Shape와 버킷, 14장 vLLM 서빙
TPOT Time Per Output Token 출력 토큰당 걸리는 시간. 첫 토큰 포함 여부·평균 방식 등 benchmark 정의를 명시한다. 7장 최적화, 14장 vLLM 서빙
vLLM vLLM, 프로젝트명 LLM 추론·서빙 프레임워크. Furiosa opt plugin은 이를 장치 엔진과 연결하지만 fxbX를 자동으로 읽는 범용 loader는 아니다. 14장 vLLM 서빙
Continuous batching Continuous batching 실행이 진행되는 동안 끝난 요청을 빼고 새 요청을 넣어 매 step의 배치를 조정하는 방식. 고정 batch 한 번의 실행과 다르다. 14장 vLLM 서빙

병렬화 단위는 Furiosa-LLM의 모델 병렬화 문서, opt plugin의 경계는 고정 커밋의 vLLM 연결 문서와 실제 코드를 함께 확인한다. 같은 TP·DP라는 단어를 사용해도 설정 단위와 지원 조합이 같다는 보장은 없다.

PTQ Post-Training Quantization 학습을 마친 모델의 가중치·활성값 표현을 양자화하는 방식. 보정 데이터·품질·실행 dtype 지원을 확인한다. 19장 양자화

Structured pruning Structured pruning 채널·head 등 구조 단위를 제거해 실제 dense 텐서 크기를 줄이는 방법. 0만 늘리는 방식과 다르다. 19장 구조적 가지치기
Distillation Knowledge distillation 큰 모델 등의 출력·중간 지식을 작은 모델의 학습 목표로 활용하는 방법. 모델이 바뀌므로 과제 품질을 재검증한다. 19장 모델 압축
NetsPresso NetsPresso, Nota의 제품명 모델 압축·변환·프로파일링을 다루는 도구와 서비스. 공개 Python client와 전체 서비스 구현의 공개 범위를 구분한다. 19장 NetsPresso
