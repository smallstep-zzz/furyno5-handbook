Chapter 07

Furiosa-LLM과 vLLM

서빙 엔진은 API로 요청을 받아 텍스트를 토큰으로 바꾸고, 여러 요청을 묶어 모델에 보냅니다. 실제 계산에 사용할 장치는 백엔드(backend)가 맡습니다.

Furiosa-LLM

Furiosa NPU에 맞춘 공식 serving 경로. FXB lifecycle과 runtime integration을 중심으로 봅니다.

vLLM

넓은 생태계의 serving engine. Furiosa에서 지원되는 backend·버전·모델 범위를 확인한 뒤 사용합니다.

개발자의 판단 순서

  1. 모델이 공식 FXB/Furiosa-LLM 지원 범위인지 확인합니다.
  2. vLLM을 쓰려면 Furiosa용 backend가 현재 release에서 지원되는지 확인합니다.
  3. KV Cache, batch, sequence length를 고정해 baseline을 만듭니다.
  4. OpenAI-compatible API latency와 NPU kernel latency를 분리 측정합니다.
# 예시 형태 — 정확한 모델/옵션은 release 문서 확인
furiosa-llm serve <model-id> --port 8000
KV Cache앞서 처리한 토큰의 Key와 Value를 저장해 다음 토큰을 생성할 때 재사용합니다. 입력이 길거나 동시 요청이 많을수록 더 많은 데이터를 저장해야 하므로 NPU 메모리 사용량을 함께 확인하세요.

버킷과 Prefill·Decode 타이밍에서 프롬프트 길이와 동시 요청이 성능에 미치는 영향을 살펴봅니다.

성능 해석

TTFT는 요청부터 첫 토큰을 받기까지의 시간입니다. TPOT는 첫 토큰 이후 출력 토큰 하나를 생성하는 데 걸리는 평균 시간입니다. 두 엔진을 비교할 때는 입력 길이, 출력 토큰 수, 동시 요청 수를 맞추세요.
