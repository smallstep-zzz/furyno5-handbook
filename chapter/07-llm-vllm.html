Chapter 07

Furiosa-LLM과 vLLM

서빙 프레임워크는 model graph보다 한 층 위에서 batching, scheduling, tokenizer, API를 책임집니다. NPU backend가 실제로 연결되는지를 따로 확인해야 합니다.

Furiosa-LLM

Furiosa NPU에 맞춘 공식 serving 경로. FXB lifecycle과 runtime integration을 중심으로 봅니다.

vLLM

넓은 생태계의 serving engine. Furiosa에서 지원되는 backend·버전·모델 범위를 확인한 뒤 사용합니다.

개발자의 판단 순서

  1. 모델이 공식 FXB/Furiosa-LLM 지원 범위인지 확인합니다.
  2. vLLM을 쓰려면 Furiosa용 backend가 현재 release에서 지원되는지 확인합니다.
  3. KV Cache, batch, sequence length를 고정해 baseline을 만듭니다.
  4. OpenAI-compatible API latency와 NPU kernel latency를 분리 측정합니다.
# 예시 형태 — 정확한 모델/옵션은 release 문서 확인
furiosa-llm serve <model-id> --port 8000
curl http://localhost:8000/v1/chat/completions
KV Cache는 영어로 유지할 만한 전문 용어입니다메모리 용량과 bandwidth를 동시에 좌우하므로, context length·batch를 늘릴 때 NPU memory pressure와 함께 관찰하세요.

성능 해석

첫 토큰까지의 시간(TTFT), 생성 중 토큰 시간(TPOT), 전체 latency, tokens/s를 분리합니다. 같은 prompt와 output token 수를 사용하지 않으면 두 backend의 숫자를 비교하지 마세요.
