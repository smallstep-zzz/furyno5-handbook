Chapter 02

소프트웨어 스택과 하드웨어

컴파일러가 빠른 코드를 만드는 일은 연산식만의 문제가 아닙니다. NPU에서는 “어디에 놓고, 언제 옮기는가”가 절반입니다.

설치된 SDK가 곧 현실이다

공식 SDK는 compiler, runtime, profiler, quantizer와 Python binding을 묶어 제공합니다. 먼저 버전을 고정하고, 예제가 실제 장비에서 돌아가는지 확인하세요.

python -m venv .venv
source .venv/bin/activate
pip install furiosa-sdk
pip show furiosa-sdk
furiosa-smi --help
주의: 이름이 비슷해도 같은 계층이 아닙니다furiosa-opt의 vISA kernel 예제, 공식 SDK의 TCL API, FuryNo5의 계획·실험 코드는 서로 다른 계약입니다. 공개 코드를 보고 임의로 “같은 compiler에 들어간다”고 가정하지 마세요.

NPU 최적화가 메모리 문제인 이유

  • 작은 연산을 너무 많이 쪼개면 kernel launch와 DMA 비용이 계산보다 커집니다.
  • layout이 맞지 않으면 transpose·repack이 매번 생깁니다.
  • FP32를 끝까지 유지하면 bandwidth와 capacity를 압박합니다.
  • 동적 shape는 compile cache와 scheduling을 어렵게 만듭니다.

권장 순서는 정확도 확인 → shape/layout 고정 → fusion → dtype/quantization → batch/concurrency입니다.
