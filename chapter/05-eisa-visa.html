Chapter 05

vISA로 NPU 명령 살펴보기

furiosa-opt의 vISA(Virtual ISA) 예제로 NPU가 데이터를 옮기고 계산하는 순서를 살펴봅니다.

덧셈 연산의 실행 순서입력 데이터를 어디에 둘지, 덧셈을 언제 실행할지, 결과를 어디에 기록할지 차례로 생각해 보세요.

언제 vISA를 살펴볼까?

TCL compiler가 충분히 좋은 schedule을 만들지 못하거나, 특정 kernel의 memory movement·pipeline을 직접 조정해야 할 때 low-level kernel을 검토합니다. 이것은 “모든 모델을 vISA로 다시 작성”하라는 뜻이 아닙니다.

# furiosa-opt 공개 kernel 저장소의 탐색 흐름 예시
./pipeline.sh ladder
./pipeline.sh check add
./pipeline.sh all add

덧셈(add)부터 시작하세요. 테스트에서 PyTorch 기준값과 출력이 일치하는지 보고, 실행 보고서에서 NPU 실행 결과를 확인하세요.

언제 NPU에서 의미가 생기나

  • 연산 자체보다 vector/tensor pipeline의 빈 시간이 병목일 때
  • 한 번의 kernel에서 local memory 재사용을 크게 늘릴 수 있을 때
  • 기존 lowering이 만드는 불필요한 transpose·materialize를 제거할 때
위험 신호하드웨어 instruction cost를 추측해 latency를 ns 단위로 말하지 마세요. 실측이 없으면 “예상”으로 표시하고, NPU run report와 분리해 기록합니다.
