Chapter 05

eISA라고 부른 층: 공개 자료의 vISA

사용자가 말한 eISA를 “명령어 수준에서 NPU 동작을 설계하는 층”으로 설명합니다. 다만 공개 Furiosa 자료에서는 이 개념이 주로 vISA (Virtual ISA)라는 이름으로 나타납니다.

이름보다 계약을 보세요vISA는 TCP(Tensor Contraction Processor)와 메모리 할당·Tensor Unit scheduling을 생각하게 해주는 low-level layer입니다. 특정 release에서 eISA라는 이름이 공식 API인지 여부는 설치된 SDK 문서로 확인하세요.

어떤 때 내려가는가?

TCL compiler가 충분히 좋은 schedule을 만들지 못하거나, 특정 kernel의 memory movement·pipeline을 직접 조정해야 할 때 low-level kernel을 검토합니다. 이것은 “모든 모델을 vISA로 다시 작성”하라는 뜻이 아닙니다.

# furiosa-opt 공개 kernel 저장소의 탐색 흐름 예시
./pipeline.sh ladder
./pipeline.sh check add
./pipeline.sh all add

각 단계는 spec, torch ground truth, test, schedule dump, run report를 남기는 식으로 작게 닫혀 있어야 합니다. 먼저 add 같은 toy op로 시작하고, 수치·layout·resource를 검증하세요.

언제 NPU에서 의미가 생기나

  • 연산 자체보다 vector/tensor pipeline의 빈 시간이 병목일 때
  • 한 번의 kernel에서 local memory 재사용을 크게 늘릴 수 있을 때
  • 기존 lowering이 만드는 불필요한 transpose·materialize를 제거할 때
위험 신호하드웨어 instruction cost를 추측해 latency를 ns 단위로 말하지 마세요. 실측이 없으면 “예상”으로 표시하고, NPU run report와 분리해 기록합니다.
