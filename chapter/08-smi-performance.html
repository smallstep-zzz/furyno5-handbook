Chapter 08

furiosa-smi를 언제 쓰는가

실행 전에는 furiosa-smi로 NPU가 보이는지 확인하세요. 실행 중에는 장치 상태를 확인하고, 어느 연산이나 전송에서 시간이 걸렸는지는 프로파일러 기록에서 찾습니다.

furiosa-smi --help
furiosa-smi info
furiosa-smi status
furiosa-smi status --interval 1
명령은 설치된 버전에 따라 다를 수 있습니다위 예시는 방향을 잡기 위한 대표 형태입니다. 먼저 furiosa-smi --help로 현재 subcommand와 출력 형식을 확인하세요.

재현 가능한 benchmark

  1. driver·SDK·model artifact의 버전을 기록합니다.
  2. 다른 작업이 장치를 함께 쓰는지 확인하고, 초기화 영향을 줄이기 위해 몇 번 먼저 실행합니다. 준비 실행(warm-up)은 본 측정에서 제외합니다.
  3. 고정된 prompt, input shape, output token 수로 반복합니다.
  4. furiosa-smi 상태와 앱 로그의 timestamp를 맞춥니다.
  5. median, p95, TTFT, TPOT, tokens/s, power/utilization을 함께 저장합니다.
# 공식 benchmark 도구의 방향을 확인하는 예시
furiosa-perf run --backend furiosa-llm --hardware-type npu ...
# vLLM 경로도 별도 backend로 비교할 수 있음
furiosa-perf run --backend vllm --hardware-type npu ...

FuryNo5 최적화 체크리스트

입력 크기·배치·정밀도·SDK·장치를 고정하고, 먼저 출력 정확도와 완료까지의 요청 시간을 기록합니다. 프로파일에서 가장 많은 시간을 차지한 구간을 골라 한 번에 한 가지를 바꿉니다.

관측한 증상먼저 바꿔 볼 것확인할 지표
NPU Task는 짧고 사이 공백이 김같은 EDF를 묶어서 제출하는 실행기와 단계별 호출을 비교합니다. 가중치만 사용하는 단계는 결과가 요청에 의존하지 않고 메모리 여유가 있을 때 재사용합니다.호스트 제출 시간, Task 사이 공백, 전체 지연 시간
작은 EDF가 연달아 중간 텐서를 씀행렬 곱셈 → bias → 활성화처럼 중간값을 함께 쓰는 연산을 TCL 한 묶음으로 컴파일합니다. 작은 묶음부터 늘려 보고, 큰 활성값을 건네거나 형상·재사용 단위가 달라지는 경계에서 분할 후보를 비교합니다.실행 호출 수, 경계를 지나는 텐서 크기, TCC 최대 RSS, p95
복사와 동기화 대기가 김중간 텐서와 반복 사용하는 가중치를 장치에 유지합니다. 연산 간 데이터 배치를 맞추고, 의존성이 없는 전송을 계산과 겹칠 수 있는지 확인합니다.H2D/D2H 시간, 중간 복사량, 요청 시간
특정 입력 길이나 동시 요청에서만 느림자주 쓰는 형상에 맞는 버킷을 준비합니다. 긴 Prefill이 Decode를 지연시키면 지원되는 스케줄러에서 청크 크기를 비교합니다.TTFT, TPOT, p95, 처리량
TCC 컴파일에서 호스트 메모리 한도 초과동시 컴파일을 하나로 낮추고 동일 버킷을 재현합니다. 한 작업도 한도를 넘으면 중간 데이터가 작고 의존성이 적은 지점에서 TCL을 나눕니다.최대 RSS, OOM 기록, 컴파일 시간, 분할 후 요청 시간

실험 기록에는 모델·입력·SDK 버전, 변경한 항목, 변경 전후 정확도와 중앙값·p95를 남깁니다. EDF를 새로 만들었다면 컴파일 시간과 최대 RSS도 기록합니다. 기존 EDF를 그대로 두고 제출 방식만 바꾼 실험과 TCL을 합쳐 EDF를 다시 만든 실험을 각각 비교하면 개선 원인을 확인할 수 있습니다.

최적화 전후에는 “평균 latency만 좋아졌다”가 아니라, 정확도·p95·전력·utilization까지 같은 실험 조건에서 비교해야 합니다.

마무리공식 FXB baseline → custom region → profiler/smi 상관분석 순서를 지키면, 개선이 실제 NPU 최적화인지 쉽게 설명할 수 있습니다.
