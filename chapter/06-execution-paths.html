Chapter 06

공식 FXB와 custom fxbx

공식 FXB는 지원 모델을 Furiosa-LLM으로 실행할 때 사용합니다. 커스텀 TCL과 .fxbx는 바꾼 연산 구현을 패키지로 묶어 따로 실행하고 검증할 때 사용합니다.

공식 FXB 경로custom TCL / fxbx 경로
소유자Furiosa compiler·runtime·Furiosa-LLMFuryNo5 또는 사용자 연구 코드
목표지원 모델을 안정적으로 serve특정 region/kernel을 실험·튜닝
artifactFXB + metadata/cache, release compatibility 계약.fxbx 등 사용자 패키지, 별도 계약
장점업데이트·서빙 경로가 단순세밀한 TCL 선택과 실험 가능
주의지원 목록과 cache 호환을 확인출력 정확도와 실행 도구의 버전 호환성 확인

공식 FXB의 일반 흐름

# 실제 옵션은 설치된 furiosa-llm/fxb 버전을 확인하세요
fxb download <model-id>
furiosa-llm serve <model-id>
# 특정 artifact를 명시하는 형태
furiosa-llm serve <model-id> --fxb /path/to/model.fxb

공식 문서는 명시적 --fxb, 모델에 포함된 FXB, cache 순서와 FuriosaIR compatibility를 설명합니다. 운영에서는 이 경로를 baseline으로 잡는 것이 좋습니다.

custom fxbx의 연구 흐름

python -m tplmachine.fxb_export ./compiled_model -o model.fxbx --standalone
fxbx run model.fxbx --input inputs.json

FuryNo5 저장소의 예제처럼 custom artifact를 만들고 직접 실행할 수 있습니다. 다만 이것은 공식 FXB와 동일한 consumer·compatibility를 자동으로 얻는다는 뜻이 아닙니다. “공식 baseline의 결과”와 “custom route의 결과”를 보고서에서 분리하세요.

권장 순서먼저 공식 FXB로 수치·성능 baseline을 확보하고, 그 다음 한 region만 custom TCL/fxbx로 바꿔 비교하세요. 전체 모델을 한 번에 custom path로 옮기면 실패 원인을 구분하기 어렵습니다.
