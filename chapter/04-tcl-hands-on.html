Chapter 04

작은 TCL region 만들기

행렬 곱셈처럼 입력과 출력이 분명한 연산 하나로 시작합니다. 아래 예제는 두 입력을 곱해 결과를 반환합니다.

작성부터 검증까지

1 · 표현

shape, dtype, layout을 고정한 TCL expression을 작성합니다.

2 · 기준값

같은 입력을 PyTorch CPU에서 계산해 reference를 저장합니다.

3 · compile

SDK compiler가 region을 거부하지 않는지 확인합니다.

4 · 측정

NPU 출력과 CPU 기준값의 오차를 확인합니다. 처음 몇 번은 준비 실행으로 빼고, 나머지 실행 시간의 중앙값을 기록합니다.

# 개념적 TCL 의사코드 — 정확한 API는 SDK release를 따르세요
x = input("x", dtype="bf16", shape=[1, 16, 4096])
w = weight("w", dtype="bf16", shape=[4096, 4096])
y = matmul(x, w)
return y
의사코드를 복사해 바로 실행하지 마세요공식 TCL Python API와 공개 furiosa-opt의 Rust/vISA 예제는 release별 문법이 다릅니다. 설치된 SDK의 샘플을 기준으로 바꾸고, 위 코드는 사고 순서만 보여줍니다.

최적화 체크리스트

  • 같은 layout을 여러 kernel이 공유하는가?
  • 중간 tensor를 host로 왕복시키지 않는가?
  • fusion으로 launch 수와 memory traffic을 줄였는가?
  • BF16/FP8/quantization을 적용해도 오차 계약을 만족하는가?
  • shape가 고정되어 compile cache를 재사용하는가?

성능을 올렸다면 반드시 “어떤 변경이 memory movement를 줄였는지” 설명할 수 있어야 합니다. 숫자 하나만 좋아진 것은 최적화의 증거가 아닙니다.

EDF 분할 기준과 TCC 컴파일 메모리에서 묶음 크기를 비교하는 방법을 확인하세요.
