기초 계산과 한국어 도식의 출처

행렬곱·einsum·reshape·전치·stride·broadcasting은 NumPy 공식 문서로 동작을 확인하고, 본문에서는 별도로 만든 작은 배열로 계산을 풀었다. 실제 값은 tensor_basics.py와 array_layout.py에서 다시 계산할 수 있다. NumPy의 stride는 바이트 수이고 PyTorch의 stride는 원소 단위이므로 예제를 옮길 때 단위를 유지해야 한다. NumPy ndarray · PyTorch Tensor.stride

01·02장의 메모리와 연산 경계 그림은 공식 furiosa-opt의 Moving Tensors와 Computing Tensors에 근거해 한국어로 재구성했다. 원본 그림을 그대로 번역한 것으로 표시하지 않고, 학습에 필요한 경로로 나누거나 단순화한 사실을 설명한다. 라이선스는 Apache-2.0 전문, 권리 표시는 Furiosa Opt NOTICE에 보존했다.

코드 검사와 NPU 실측의 구분

이 핸드북의 예제는 새 RNGD 실측 결과로 제시하지 않는다. 새로 추가한 NumPy 기초 예제 두 개는 CPU에서 실제 실행해 배열 값과 shape·stride·메모리 공유를 확인했다. 장치 호출 API·정의 파일·CLI 구성·버전·실행 전제는 소스와 대조하고, 완전한 Python 예제의 문법을 검사했다. 예를 들어 5장의 병렬 컴파일 예제는 소스가 spawn 방식의 프로세스를 사용함을 확인하고 main() 보호를 추가했다. 이는 재현성을 높이는 코드 검토 결과이지 NPU 통과 결과는 아니다. 프로세스 생성 구현

8장의 Schedule Viewer 수치는 컴파일러가 만든 정적 schedule의 비용이다. 실제 host 대기·전송·장치 상태·요청 분포를 포함한 benchmark 결과로 바꾸어 읽지 않는다. Schedule Viewer 설명

  4. 실행 증거: 준비·적재·실행의 성공 또는 실패, 실제 NPU Task, CPU fallback 정책, 반복 실행·새 입력·새 프로세스 적재 결과.
